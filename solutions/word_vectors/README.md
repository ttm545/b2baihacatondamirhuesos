# Поиск писем по векторам слов

Эксперимент запускает штатный `PeriodRanker` с семантическим расширением в BM25. Используются тот же индекс частот, лемматизация, поправка на длину письма, веса темы и служебных слов, парсер дат, глубина 60 и те же признаки и коэффициенты финальной пересортировки. Отдельный признак сходства написания по триграммам работает как раньше.

Точная часть BM25 использует исходные постинги лемм. Для дополнительного сигнала вместо группы с одинаковыми первыми пятью буквами берётся до 24 лемм архива с косинусной близостью от 0,45 по Navec. Вхождения этих лемм складываются с весом косинуса до насыщения частоты в BM25. IDF считается по числу писем ящика, где встречается хотя бы одна лемма из группы. Вес дополнительного сигнала остаётся 0,15. Совпадения группы в теме учитываются по тому же коэффициенту 0,25, с поправкой на близость. При равных группах и весах результат совпадает с исходным префиксным ранжированием.

## Запуск

Установите зависимости из корня репозитория. Модель и результаты храните отдельно от Git.

```sh
python -m pip install -r requirements-baseline.txt -r solutions/word_vectors/requirements.txt
mkdir -p .cache
curl -fL https://storage.yandexcloud.net/natasha-navec/packs/navec_hudlit_v1_12B_500K_300d_100q.tar \
  -o .cache/navec_hudlit_v1_12B_500K_300d_100q.tar
python -m solutions.word_vectors --model .cache/navec_hudlit_v1_12B_500K_300d_100q.tar \
  --data-dir data --mailbox box-84bd433469cb --as-of 2028-09-14 \
  --query 'Что вчера сняли с борта на причал?'
```

Для контроля запустите поиск с `--similarity 1`. Это отключает дополнительный сигнал BM25. Финальный профиль `period`, включая триграммы, работает как раньше.

```sh
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 python -m solutions.word_vectors.benchmark \
  --model .cache/navec_hudlit_v1_12B_500K_300d_100q.tar --data-dir data --out .cache/word-vectors
python -m unittest solutions.word_vectors.test_search
```

Бенчмарк записывает отдельные выдачи глубиной 100 и `results.json`. Порог 0,45 выбран по nDCG@10 на 44 формулировках `tune`. 32 перефразировки `test` и восемь ручных примеров при выборе не использовались. Исходный публичный набор включает запросы тех же семейств, что и `tune`.

## Результат

| Набор и режим | Recall@5 | Recall@10 | nDCG@10 |
| --- | ---: | ---: | ---: |
| VK, 99 запросов · `period` | 0,8516 | 0,9322 | 0,9906 |
| VK, 99 запросов · `period` без префиксов | 0,8471 | 0,9287 | 0,9864 |
| VK, 99 запросов · `period` с векторами | 0,8491 | 0,9280 | 0,9859 |
| 32 перефразировки · `period` | 0,5437 | 0,7538 | 0,7103 |
| 32 перефразировки · `period` без префиксов | 0,5271 | 0,7434 | 0,6985 |
| 32 перефразировки · `period` с векторами | 0,4963 | 0,7466 | 0,6811 |

В восьми ручных примерах целевое письмо не имело общих пятибуквенных префиксов лемм с темой запроса. Оно оказалось выше выбранного похожего письма в 7 из 8 случаев с векторами, в 5 из 8 без дополнительного сигнала и в 4 из 8 у обычного `period`. Целевое письмо попало в топ‑10 в 6 из 8 случаев с векторами и в 3 из 8 у обычного `period`. Это небольшой диагностический набор, по которому проверяется место конкретного письма.

Локальный p99 вызова поиска при K=100 на Apple M4 составил 6,8 мс на публичных запросах и 7,3 мс на отложенных. HTTP и очередь не измерялись. Подготовка матрицы словаря с загрузкой модели заняла дополнительно 0,27 с. [Navec](https://github.com/natasha/navec)
