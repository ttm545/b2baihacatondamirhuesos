# Поиск писем по векторам слов

Эксперимент пересортировывает все письма из распознанного периода в выбранном ящике. Индекс хранит частоту лемм в письме и нормализованные векторы слов из Navec. Каждое вхождение слова в тему получает тройной вес. Для каждой леммы запроса выбираются до 24 соседних слов из словаря архива с косинусной близостью выше порога. Точное совпадение весит 1, в том числе для слов без вектора. Вес соседнего слова растёт линейно от 0 на пороге до 1 при полном совпадении векторов.

Взвешенные вхождения соседей складываются. Балл насыщается по формуле BM25 с поправками на длину письма и частоту семантических совпадений по архиву. Письма вне периода дополняют выдачу обычным текстовым поиском. Запросы без периода тоже используют обычный поиск. Разметка нужна только для оценки и выбора одного порога.

## Запуск

Установите зависимости из корня репозитория. Модель и результаты храните отдельно от Git.

```sh
python -m pip install -r requirements-baseline.txt -r solutions/word_vectors/requirements.txt
mkdir -p .cache
curl -fL https://storage.yandexcloud.net/natasha-navec/packs/navec_hudlit_v1_12B_500K_300d_100q.tar \
  -o .cache/navec_hudlit_v1_12B_500K_300d_100q.tar
python -m solutions.word_vectors --model .cache/navec_hudlit_v1_12B_500K_300d_100q.tar \
  --data-dir data --mailbox box-84bd433469cb --as-of 2028-09-14 \
  --query 'Что вчера сняли с борта на причал?'
```

Для контроля с одной и той же формулой частоты запустите поиск с `--similarity 1`. Соседи отключаются, остаются точные совпадения лемм.

```sh
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 python -m solutions.word_vectors.benchmark \
  --model .cache/navec_hudlit_v1_12B_500K_300d_100q.tar --data-dir data --out .cache/word-vectors
python -m unittest solutions.word_vectors.test_search
```

Бенчмарк записывает отдельные выдачи глубиной 100 и `results.json`. Порог 0,35 выбран по nDCG@10 на 44 формулировках `tune`. 32 перефразировки `test` и восемь ручных примеров при выборе не использовались. Исходный публичный набор включает запросы тех же семейств, что и `tune`.

## Результат

| Набор и режим | Recall@5 | Recall@10 | nDCG@10 |
| --- | ---: | ---: | ---: |
| VK, 99 запросов · `period` | 0,8516 | 0,9322 | 0,9906 |
| VK, 99 запросов · точные леммы | 0,8245 | 0,9051 | 0,9588 |
| VK, 99 запросов · векторы слов | 0,8260 | 0,9051 | 0,9587 |
| 32 перефразировки · `period` | 0,5437 | 0,7538 | 0,7103 |
| 32 перефразировки · точные леммы | 0,4922 | 0,7166 | 0,6721 |
| 32 перефразировки · векторы слов | 0,5218 | 0,7141 | 0,6591 |

В восьми ручных примерах целевое письмо не имело общих пятибуквенных префиксов лемм с темой запроса. Целевое письмо оказалось выше выбранного похожего письма в 5 из 8 случаев с векторами и в 4 из 8 у `period`. Целевое письмо попало в топ‑10 в 6 из 8 случаев с векторами и в 3 из 8 у `period`. Это небольшой диагностический набор, по которому проверяется место конкретного письма.

Локальный p99 вызова поиска при K=100 на Apple M4 составил 5,8 мс на публичных запросах и 3,0 мс на отложенных. HTTP и очередь не измерялись. Дополнительный индекс с загрузкой модели построился за 0,46 с поверх индекса `period`. [Navec](https://github.com/natasha/navec)
