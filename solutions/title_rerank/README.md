# Поиск с оценкой тем писем через Qwen

Изолированный вариант использует обычный `period` для подбора кандидатов. В первых десяти позициях Qwen сравнивает содержательную часть запроса с явно указанной темой каждого письма. Одинаковые темы оцениваются один раз. Тело, подставленная первая строка и векторы писем не используются.

Модель превращает разницу логитов `yes` и `no` в число от 0 до 1. К линейному баллу позиции `period` от 1 до 0 добавляется этот балл, умноженный на `VK_SUBJECT_WEIGHT`. Переставляются только оценённые письма. У писем без явной темы, писем вне распознанного периода и позиций после первой десятки порядок остаётся прежним. Для запроса без смысловой части работает обычный `period`.

## Запуск

Установите зависимости из корня репозитория. В первом запуске Transformers скачивает веса. После загрузки можно использовать `HF_HUB_OFFLINE=1`.

```sh
python -m pip install -r requirements-baseline.txt -r requirements-api.txt -r solutions/title_rerank/requirements.txt
VK_DATA_DIR=data VK_SUBJECT_DEVICE=mps \
  python -m uvicorn solutions.title_rerank.api:create_app --factory --port 8001
```

На CPU используйте `VK_SUBJECT_DEVICE=cpu` или опустите переменную. Вес по умолчанию 0,35. `VK_SUBJECT_WEIGHT=0` запускает тот же интерфейс с обычным `period` без загрузки модели.

```sh
python -m solutions.title_rerank.benchmark --data-dir data --device mps --out .cache/title-rerank
python -m unittest solutions.title_rerank.test_searcher
```

Бенчмарк сравнивает веса 0,10 / 0,20 / 0,35 / 0,50 на 44 разработочных перефразировках. Выбранный по nDCG@5 положительный вес затем сравнивается с обычным `period` на 32 отложенных перефразировках и 99 публичных запросах. Команда записывает отдельные выдачи, оценки тем и агрегированные результаты.

| Срез | Recall@5 у обоих вариантов | nDCG@5, period → с Qwen | nDCG@10, period → с Qwen |
| --- | ---: | ---: | ---: |
| 99 публичных запросов | 0,8516 | 0,9869 → 0,9857 | 0,9906 → 0,9893 |
| 32 отложенные перефразировки | 0,5437 | 0,6518 → 0,6532 | 0,7103 → 0,7117 |

На отложенном срезе Recall@2 вырос с 0,3708 до 0,3770. На публичном Recall@1 снизился с 0,5583 до 0,5549. Модель оценивала темы в 55 из 99 публичных запросов и в 25 из 32 отложенных, а порядок поменялся в 8 и 4 запросах соответственно.

Локальный p99 вызова поиска на Apple M4 через MPS составил 863 мс на публичном срезе и 996 мс на отложенном. Замер включает поиск и вызов модели, выполняется последовательно при K=10 и не включает HTTP или очередь. Одна секунда при серверной нагрузке этим замером не подтверждается.
