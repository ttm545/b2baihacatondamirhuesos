# Векторный поиск по почте

Поиск строит векторный индекс до обработки запросов. Энкодер получает тему и начало письма, а индекс хранит нормализованный вектор и связь с ID письма. Во время поиска энкодер обрабатывает запрос отдельно. Внутри нужного ящика поиск сортирует письма по косинусному сходству. Письма с известной датой позже даты запроса исключаются.

## Варианты для демо

| `VK_CONTEXT_MODE` | Как ранжирует |
| --- | --- |
| `period` | Текущий текстовый движок для всех запросов. |
| `vector` | Выдача векторного индекса. Когда распознан период, его письма идут первыми. |
| `auto` | С датой используется `period`. Без даты используется векторный индекс. |
| `hybrid` | С датой используется `period`. Без даты результаты BM25 и векторного индекса объединяются по позициям двух выдач. |
| `context` | С датой переставляет письма внутри первой десятки `period` с помощью контекста, полученного при обучении на Qwen. Без даты работает как `hybrid`. [Обучение и сравнение](QWEN_CONTEXT.md) |
| `ensemble` | Смешивает три ранга для датированных запросов. Без даты использует BM25, RuBERT, проекцию Qwen и мягкую свежесть. [Сравнение и команды](FINAL_HACKATHON.md) |

Полный индекс RuBERT содержит все **16 376 писем**. В библиотеке поиска модель запроса и энкодер писем уже разделены. [Модель, индексация и зависимости RuBERT](README.md)

Для демонстрации запустите приложение с нужным режимом. Пример для PowerShell после построения полного индекса RuBERT по [README](README.md):

```powershell
$env:VK_DATA_DIR = "data"
$env:VK_CONTEXT_MODE = "auto"
$env:VK_CONTEXT_ENCODER = "rubert"
$env:VK_CONTEXT_INDEX = ".cache/tiny-fast.npz"
$env:VK_TINY_MODEL = ".cache/rubert-tiny-retriever"
$env:VK_TINY_PROJECTION = "solutions/tiny_encoder/assets/projection-80.npz"
$env:VK_TINY_ADAPTER = "solutions/tiny_encoder/assets/adapter-80.npz"
python -m uvicorn solutions.tiny_encoder.routed_api:create_routed_app --factory --host 127.0.0.1 --port 8000
```

Откройте [почту](http://127.0.0.1:8000/) и попробуйте один запрос с датой, затем другую формулировку без даты. Для сравнения запустите второй процесс с `VK_CONTEXT_MODE=period` или `VK_CONTEXT_MODE=hybrid` на другом порту.

## Проверка запросов без даты

На всех 99 исходных запросах и 32 отложенных перефразировках с датой `auto` и `hybrid` дали те же результаты, что `period`. Для отдельной проверки из тех же формулировок удалили дату, сохранили ящик, временную границу и исходную разметку. Эта проверка показывает, насколько хорошо поиск находит **исходное целевое письмо без календарной подсказки**. На других днях могут быть подходящие письма, которых нет в исходном эталоне.

| Режим без даты | 99 исходных · nDCG@10 | 99 исходных · Recall@10 | 32 перефразировки · nDCG@10 | 32 перефразировки · Recall@10 |
| --- | ---: | ---: | ---: | ---: |
| `period` (текстовый поиск) | 0,1739 | 0,2670 | 0,0533 | 0,0679 |
| `auto` (RuBERT) | 0,1976 | **0,3266** | 0,0991 | 0,1842 |
| `hybrid` (BM25 и RuBERT) | **0,2034** | 0,3138 | **0,1177** | **0,1870** |

Для первого показа используйте `hybrid`. Этот режим дал лучший nDCG@10 на обоих срезах с замаскированной датой и сохранил выдачу `period` на датированных запросах.

Локальный HTTP-бенчмарк `hybrid` на CPU i5-13420H, один Uvicorn, восемь клиентов и K=10. С датой p99 составил **79,9 мс**, с замаскированной датой — **93,7 мс**. Внутри API получено 47,1 и 92,5 мс соответственно. В каждом из двух прогонов успешны все 1 000 запросов после прогрева.

```sh
python -m solutions.tiny_encoder.routed_eval --data-dir data --model .cache/rubert-tiny-retriever --projection solutions/tiny_encoder/assets/projection-80.npz --index .cache/tiny-fast.npz --adapter solutions/tiny_encoder/assets/adapter-80.npz
```

## Локальный эксперимент Qwen

Использован текстовый энкодер **Qwen3-VL-Embedding-2B** в Q4_K_M. Письма и запросы кодируются независимо. Вектор имеет **2 048 координат**. Веса занимают **1,11 ГБ**. Служба Qwen работает на `127.0.0.1` и получает тексты только с этого компьютера. [Модель Qwen](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B) · [Версия весов GGUF](https://huggingface.co/gorse-io/Qwen3-VL-Embedding-2B-GGUF/tree/608fc16365b286124e1f908e2603a981a3759994) · [Версия llama.cpp](https://github.com/ggml-org/llama.cpp/releases/tag/b12240)

Результат первого прогона на i5-13420H: **59 писем одного ящика за 50,8 с**. Индекс занимает **243 КБ**. На трёх запросах, для которых эта дата известна, Qwen показал **0,652 nDCG@10**. Это проверка работоспособности на одном дне. По наблюдаемой скорости полная индексация Qwen займёт на этой машине примерно четыре часа. Индекс RuBERT даёт полноархивный режим уже сейчас.

Пилот без даты на подготовленном индексе Qwen: по 24 успешных вызова поиска. p99 составил **238 мс при одном клиенте** и **1 957 мс при восьми**. Измерение включает кодирование запроса через локальный `llama-server` и поиск по индексу. Поэтому Qwen подходит для отдельного эксперимента, а для демонстрации при целевом CPU p99 меньше секунды используем компактный режим. Отдельный файл векторов всех 99 запросов сформирован и занимает 417 КБ.

Запуск локального энкодера. Укажите путь к проверенному `llama-server.exe` и GGUF. SHA‑256 файла весов — `feec6d40b22cacd3860863fb2e2fa2c3d20e4842dd6a65f290a3d501ab44ed1e`.

```sh
llama-server --model .cache/Qwen3-VL-Embedding-2B-Q4_K_M.gguf --alias qwen-mail-feec6d40b22c --embedding --pooling last --embd-normalize 2 --host 127.0.0.1 --port 18767 -c 4096 -b 2048 -ub 2048 -np 8 -t 8 -tb 8 -ngl 0
```

Пилот на одном дне и отдельный экспорт векторов 99 запросов:

```sh
python -m solutions.tiny_encoder.qwen_embed index --data-dir data --index .cache/qwen-pilot.npz --cache .cache/qwen-docs.sqlite --scope-mailbox box-84bd433469cb --scope-day 2028-09-13
python -m solutions.tiny_encoder.qwen_embed search --data-dir data --index .cache/qwen-pilot.npz --scope-mailbox box-84bd433469cb --scope-day 2028-09-13 --mailbox box-84bd433469cb --as-of 2028-09-14 --query "Уведомления о прибытии автомашин"
python -m solutions.tiny_encoder.qwen_embed index-queries --data-dir data --index .cache/qwen-query-vectors.npz
```

Для полноархивного Qwen повторите команду `index` без `--scope-mailbox` и `--scope-day` и с новым файлом `--index`. Используйте прежний `--cache`, если хотите продолжить после прерывания или переиспользовать векторы из пилота. Затем выставьте `VK_CONTEXT_ENCODER=qwen` и укажите путь к полному индексу в `VK_CONTEXT_INDEX`. Обычный поиск кодирует каждый новый запрос на лету. Экспорт запросов позволяет отдельно изучать готовые запросные векторы. Веса, индексы и кэш хранятся вне Git.
