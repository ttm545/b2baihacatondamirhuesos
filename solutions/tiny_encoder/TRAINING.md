# Обучение RuBERT на разных почтовых базах

Для каждой базы обучен отдельный адаптер поверх одинаковых замороженных RuBERT и быстрой проекции писем. PyTorch сравнивает релевантное письмо с трудными отрицательными кандидатами, увеличивая вес ошибок возле первых пяти позиций. На валидации сравнивались адаптация запроса и двухсторонняя адаптация, две силы регуляризации и три числа эпох. Конфигурации выбирались по nDCG@5 на валидации. В каждом из пяти прогонов выбрана адаптация запросов. Локальные индексы и данные в Git отсутствуют.

## Отдельные обучения и перенос на VK

База сравнения — быстрый RuBERT без старого адаптера. В последнем столбце все модели проверены на тех же 32 перефразировках VK. У базы на них Recall@5 равен 0,5255 и nDCG@5 0,6054. У ранее выпущенного VK-адаптера — 0,5401 и 0,6299 соответственно.

| База обучения | Обучение / валидация / тест | Recall@5 на своём тесте | nDCG@5 на своём тесте | Recall@5 на VK |
| --- | ---: | ---: | ---: | ---: |
| VK | 51 / 24 / 32 | 0,5255 → 0,5067 | 0,6054 → 0,6138 | 0,5067 |
| SARA / Enron | 96 / 24 / 30 | 0,0240 → 0,0395 | 0,0718 → 0,0915 | 0,4897 |
| ART·E / Enron | 300 / 45 / 60 | 0,2000 → 0,2167 | 0,1260 → 0,1287 | 0,5012 |
| Vectrix | 300 / 45 / 184 | 0,6008 → 0,5911 | 0,5276 → 0,5338 | 0,5300 |
| TREC / W3C | 20 / 5 / 125 | 0,1600 → 0,2240 | 0,1208 → 0,1740 | 0,5106 |

- VK разделён по семействам запросов. Дополнительный прогон использовал все исходные запросы восьми разработочных шаблонов и размеченные отрицательные примеры других тем. На четырёх отложенных семействах получились Recall@5 0,5284 и nDCG@5 0,6215.
- SARA разделён по темам. Все три формулировки одного задания попадают в один раздел. Срезы содержат 32, 8 и 10 тем. [SARA](https://github.com/JackMcKechnie/SARA)
- ART·E обучался на трёх ящиках из Train, валидация на четвёртом ящике, тест на другом ящике из Test. В Vectrix использованы разделы издателя. Для ART·E и Vectrix проверено отсутствие пересечений Message-ID целевых писем между обучением, валидацией и тестом. [ART·E](https://huggingface.co/datasets/corbt/enron_emails_sample_questions) · [Vectrix](https://huggingface.co/datasets/TonicAI/vectrix-art-e)
- W3C использует официальные 25 тренировочных тем, из которых 5 оставлены для выбора конфигурации. Тест использует 125 тем и выборку писем W3C. [TREC](https://trec.nist.gov/data/t14_enterprise.html) · [Архив рассылок](https://tides.umiacs.umd.edu/webtrec/trecent/parsed_w3c_corpus.html)

## Тематическая голова VK

Дополнительный вариант обучает 12 линейных классификаторов тем на векторах писем. На входе RuBERT сопоставляет запрос с векторами известных тем, а классификатор добавляет к косинусному баллу вероятность темы письма. Вес тематической оценки 0,30. Проверка выполнена в пяти блоках, сгруппированных по паре «ящик и календарный день». Для каждой строки параметры обучены без её блока. Другие даты того же типа писем могли использоваться для обучения. Поэтому этот протокол измеряет перенос на другие экземпляры известных типов, а раздел выше — перенос на непохожие семейства запросов.

| Срез | Recall@5 без головы → с головой | nDCG@5 без головы → с головой | MRR@5 без головы → с головой |
| --- | ---: | ---: | ---: |
| 99 исходных запросов, разделение по ящику и дню | 0,7903 → **0,8260** | 0,8924 → **0,9570** | 0,9498 → **0,9818** |
| 32 перефразировки, день исходного запроса исключён | 0,5255 → **0,5900** | 0,6054 → **0,7123** | 0,7109 → **0,8125** |

Recall@100 равен 1,0000 на обоих срезах. При идеальной сортировке Recall@5 ограничен 0,8630 для 99 публичных запросов и 0,8526 для 32 перефразировок, поскольку часть запросов имеет больше пяти релевантных писем. Веса тематической головы для запуска переобучены на всех 99 видимых исходных запросах после проверки по блокам. Закрытые запросы организаторов в обучении и оценке не использовались.

У тематической головы серверный p99 составил 132,6 мс при K=5 и 185,1 мс при K=100. Локальный Uvicorn на Windows, восемь клиентов и по 1 000 успешных HTTP-запросов на глубину. Loopback p99 составил 135,7 и 194,8 мс соответственно.

Отдельно проверено объединение готовых выдач `period` и предыдущего адаптированного RuBERT. Доля векторного ранга 0,25 выбрана на 44 перефразировках `tune` с контролем nDCG@5 на исходных запросах их восьми тем. На неизменных 32 отложенных перефразировках Recall@5 вырос с 0,5437 у `period` до 0,5687, nDCG@10 с 0,7103 до 0,7163. На публичных 99 Recall@5 сохранился 0,8516, nDCG@10 снизился с 0,9906 до 0,9867. Это сравнение готовых выдач через `fuse`, p99 для этого объединения отдельно не измерялся.

## Повтор запуска

Быстрый индекс VK и модель готовятся по [основному README](README.md). Для обучения по нескольким корпусам дополнительно нужен `pyarrow`. `--public-root` указывает на каталог `sara/`, `arte/`, `vectrix/`, `w3c/`. В каждом подкаталоге должен быть `vk-jsonl/` с исходным проверочным набором из предыдущих замеров команды. Для ART·E нужны исходные `emails-*.parquet`, `questions-0000.parquet` из Test и `questions-train.parquet` из Train. Для Vectrix нужны `tasks_eval.parquet` и `tasks_train.parquet`. Для W3C нужны `w3c-emails-part*.tar.gz`, темы и `ent05.known-item.training-qrels`.

```sh
python -m solutions.tiny_encoder.train_corpora --vk-data data --public-root .cache/public-mail-benchmarks --model .cache/rubert-tiny-retriever --projection solutions/tiny_encoder/assets/projection-80.npz --vk-index .cache/tiny-fast.npz --older-adapter solutions/tiny_encoder/assets/adapter-80.npz --out .cache/multi
python -m solutions.tiny_encoder.train_topics --data-dir data --model .cache/rubert-tiny-retriever --projection solutions/tiny_encoder/assets/projection-80.npz --index .cache/tiny-fast.npz --out .cache/vk-topics.npz
```

`train_corpora` пишет отдельные NPZ и JSON для каждой базы. Для запуска поиска с одним из этих адаптеров используйте `--metric-adapter .cache/multi/<база>.npz` или `VK_TINY_METRIC_ADAPTER`. Для тематической головы включены готовые коэффициенты: `--topic-adapter solutions/tiny_encoder/assets/vk-topics.npz` или `VK_TINY_TOPIC_ADAPTER` с тем же путём. На один запуск выбирается один адаптер.
