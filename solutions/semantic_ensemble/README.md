# Смешанный отбор топ‑30 для ensemble

Ветка основана на `task/vk-search-qwen-index` Дамира, коммит `da14429`. Новый режим влияет на запросы, где пользователь указывает день или период.

1. Запрос разбирается штатным парсером даты и темы. Обычный и семантический BM25 ищут по полному доступному ящику. Штатный календарный отбор сохраняет приоритет писем внутри указанного периода.
2. Для всех писем периода каждый балл делится на максимальный балл своего канала. Затем складываются **90% обычного BM25 и 10% семантического BM25**. В семантическом канале сохраняются формула BM25, веса темы и служебных слов, IDF и насыщение частоты. Вместо первых пяти букв используются до 24 соседних лемм из Navec с косинусом от 0,45. Вхождения соседей взвешиваются по косинусу, коэффициент дополнительного канала равен 0,15.
3. До 30 писем из нужного периода получают исходные текстовые и контекстные признаки ансамбля. Сохраняются веса `period` / `period:cover` / `context` 0,35 / 0,20 / 0,45 и порог совпадения темы 0,5. Если совпадение сильное, внутри новой выборки используется текстовый порядок `period`. Остальную выдачу дополняет штатный `period`. Запросы без даты обслуживает исходный полноархивный режим ансамбля.

## Запуск

Подготовьте компактный индекс RuBERT по [инструкции Дамира](../tiny_encoder/README.md). Скачайте [русские векторы Navec](https://github.com/natasha/navec/blob/master/README.md#downloads) и храните их локально.

```sh
python -m pip install -r requirements-api.txt -r solutions/semantic_ensemble/requirements.txt
mkdir -p .cache
curl -fL https://storage.yandexcloud.net/natasha-navec/packs/navec_hudlit_v1_12B_500K_300d_100q.tar -o .cache/navec.tar
```

```sh
assets=solutions/tiny_encoder/assets
export VK_DATA_DIR=data
export VK_CONTEXT_MODE=ensemble
export VK_TINY_MODEL=.cache/rubert-tiny-retriever
export VK_TINY_PROJECTION="$assets/projection-80.npz"
export VK_TINY_ADAPTER="$assets/adapter-80.npz"
export VK_CONTEXT_INDEX=.cache/tiny-fast.npz
export VK_CONTEXT_ADAPTER="$assets/qwen-context.npz"
export VK_WORD_VECTORS=.cache/navec.tar
python -m uvicorn solutions.semantic_ensemble.api:create_app --factory --port 8001
```

Вес семантического канала на первом этапе задаётся переменной `VK_SEMANTIC_WEIGHT`. Значение `0` использует только обычный BM25, `1` — предыдущий отбор только семантическим BM25. По умолчанию используется `0.10`.

```sh
python -m solutions.semantic_ensemble.benchmark \
  --data-dir "$VK_DATA_DIR" --model "$VK_TINY_MODEL" --projection "$VK_TINY_PROJECTION" \
  --index "$VK_CONTEXT_INDEX" --adapter "$VK_TINY_ADAPTER" --context "$VK_CONTEXT_ADAPTER" \
  --config "$assets/ensemble.json" --word-vectors "$VK_WORD_VECTORS" --out .cache/semantic-ensemble
python -m unittest solutions.semantic_ensemble.test_search
```

Бенчмарк подбирает вес семантического канала между 0,10 / 0,25 / 0,50 / 0,75 / 0,90 на 44 разработочных перефразировках по nDCG@5, Recall@5 и nDCG@10. При равенстве выбирается меньший вес. Публичный набор и 32 отложенных перефразировки используются для оценки. Результаты включают выдачи, финальные метрики и отдельный Recall кандидатов. Задержка измеряется для K=10, после прогрева, при одном клиенте и без HTTP.

## Результаты

| Набор | Режим отбора | Recall кандидатов | Финальный Recall@5 | nDCG@5 | nDCG@10 | p99, мс |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 99 публичных | Исходный ensemble, топ‑20 | 97,94% | 85,16% | 0,9869 | 0,9906 | 5,1 |
| 99 публичных | Обычный BM25, топ‑30 | 98,71% | 85,16% | 0,9874 | 0,9912 | 7,2 |
| 99 публичных | Семантический BM25, топ‑30 | 96,44% | 84,17% | 0,9790 | 0,9782 | 11,0 |
| 99 публичных | Смесь 90/10, топ‑30 | 98,71% | 85,16% | 0,9869 | 0,9906 | 11,0 |
| 32 отложенные | Исходный ensemble, топ‑20 | 88,62% | 56,25% | 0,6537 | 0,7168 | 3,3 |
| 32 отложенные | Обычный BM25, топ‑30 | 91,12% | 56,25% | 0,6550 | 0,7183 | 3,7 |
| 32 отложенные | Семантический BM25, топ‑30 | 93,80% | 56,87% | 0,6578 | 0,7147 | 9,9 |
| 32 отложенные | Смесь 90/10, топ‑30 | 92,37% | 56,87% | 0,6582 | 0,7180 | 9,5 |

При равной глубине 30 смесь подняла Recall кандидатов на отложенных запросах с 91,12% до 92,37%. На запрос «короба с борта вчера» она добавила два размеченных письма. Финальное качество улучшилось на глубине 5 и почти совпало на глубине 10. Замер задержки сделан локально на Apple M4.
