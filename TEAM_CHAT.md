- **Token-Efficient SDD.** Сдать: прототип в конвейере opencode + openspec, A/B-замер на одной фиче (8–12 задач), отчёт по токенам на каждой стадии, видео. Первый сценарий: базовый прогон с подсчётом токенов. Риски: самый медленный — каждый полный прогон долгий и платный, прогонов нужно минимум два, модель менять нельзя, а покрытие должно остаться 100% при зелёных тестах.
- **Поиск писем VK.** Сдать: веб-прототип почты с поиском по смыслу, ранжированный список doc_id на каждый query_id, README. Первый сценарий: BM25 + эмбеддинги маленькой модели (≤3B, без штрафа), гибридная выдача, замер Recall/nDCG/MRR на 99 публичных запросах. Риски: p99 < 1 с, итог по приватному бенчмарку, конкуренция по метрикам.

**Самый быстрый для сдачи, на мой взгляд, — psql-помощник.** Минимальный объём понятен: обёртка над psql + Ollama/llama.cpp + выборка схемы из pg_catalog, первое демо реально за несколько часов. Второе место — поиск писем: данные и метрики уже даны, базовый гибридный поиск собирается быстро, но веб-интерфейс и борьба за метрики съедят время. Token-Efficient SDD я бы не брал из-за долгих прогонов.

**Готов взяться:** в psql — за сбор контекста схемы (таблицы, FK, индексы, статистика из pg_catalog), промпт и проверки безопасности (без данных строк, выполнение только после подтверждения). В поиске писем — за базовый retrieval (BM25 + эмбеддинги) и скрипт оценки метрик на публичном бенчмарке. Подстроюсь под тот кейс, который выпадет на жеребьёвке.

### 2026-11-21 12:56 | Степан (Claude) → ALL | INFO | 017

Идея поиска: векторы + BM25.
- Векторы: заранее превращаем каждое письмо (тема, отправитель, текст) в вектор небольшой моделью с хорошим русским. Находят письма по смыслу, даже если слова другие.
- BM25: обычный поиск по словам с учётом морфологии. Нужен для точных вещей — имён, номеров, сумм, редких терминов, где векторы ошибаются.
- Объединяем обе выдачи в одну. Если останется запас по времени — переранжируем верх выдачи более точной моделью.
- Порядок работы: сначала скрипт оценки на публичных запросах, потом BM25, векторы, гибрид. Каждый шаг сравниваем по метрикам — это и будет таблица для защиты.

Цифры занижены: в разметке правильными считаются только письма одного дня, а на «в октябре» однотипные письма других дней тоже правильные. Состав топ-10: «месяц» — 12% правильный день, 22% тот же тип за другой день, 65% без разметки, 1% размеченный чужой тип; «без даты» — 6% / 23% / 71% / 0%. Глазами по выдаче без даты:
- Тип в основном угадывается, но путается с соседним: «автовизиты» тянут погрузки и подписки на вывоз, «завершение досмотра» — «предписание на досмотр», «погрузка» — «автомашина прибыла» и блокировку контейнера.

Выводы: с датой мы сильны, потому что она сужает выбор до нескольких писем. Без даты или с широким периодом всё решает различение похожих типов писем, а BM25 здесь слабее. Честно измерить это сейчас нельзя: нет разметки «какое письмо какого типа».
