# Переранжирование писем внутри периода

Эксперимент для v1.1 приостановлен по сообщению 066 в `TEAM_CHAT.md`. Рабочий вариант v1.0 — `dated:bm25`.

## Задержка v1.0 на сервере

До выпуска измеряли API `cc427e4` с `dated:bm25` на сервере с одним Intel Xeon vCPU. В каждом прогоне 8 клиентов, 1 000 успешных вызовов по 99 запросам, один Uvicorn и HTTP через `127.0.0.1`.

| K | Клиент p50 / p95 / p99, мс | API `took_ms` p99, мс |
| ---: | ---: | ---: |
| 10 | 28,255 / 66,055 / 98,645 | 53,627 |
| 100 | 57,475 / 98,440 / 119,829 | 68,520 |

`took_ms` начинается при входе в маршрут FastAPI и не видит ожидание до этого момента. На защите используем клиентский замер по loopback: он включает ожидание и обработку HTTP на сервере, без внешней сети и TLS. Значения p99 из разных распределений нельзя точно разложить вычитанием.

## Модели и правила сравнения

Числа получены через `sum(p.numel() for p in model.parameters())`.

| Модель | Параметры |
| --- | ---: |
| [Mixedbread mxbai-rerank-large-v2](https://huggingface.co/mixedbread-ai/mxbai-rerank-large-v2) | 1 543 714 304 |
| [BAAI bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) | 567 755 777 |
| [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) | 595 776 512 |
| [USER2-base](https://huggingface.co/deepvk/USER2-base), векторизатор для сравнения | 149 014 272 |

Модель оценивает тему запроса и первые токены письма вместе, максимум 256 токенов на пару. При распознанном периоде меняются места только у писем этого периода среди первых N, без периода — у первых N писем. N равен 10, 20 или 30. Остальные кандидаты остаются в порядке `dated:bm25`.

Бюджет по умолчанию — 400 мс от входа в `search()`. Если модель занята или не успела, возвращаем порядок BM25. Одновременно выполняется не больше одного задания, очереди моделей нет. Уже начатый батч может закончиться в фоне, но дальнейшие батчи проверяют дедлайн. Это ограничение ожидания модели, а не гарантия p99 всей системы на произвольном оборудовании. Поэтому p99 под нагрузкой измеряем отдельно.

Модель и N выбираем на `tune`; на `test` запускаем только выбранную конфигурацию. 99 исходных публичных запросов используются как проверка на ухудшение. Прогоны качества дожидаются освобождения модели между запросами, HTTP-прогон использует восемь клиентов без таких пауз.

## Состояние на момент паузы

На M4 в FP16 с бюджетом 400 мс все три модели сохранили nDCG@10 **0,975632** на 99 публичных запросах. Результаты ниже одинаковы для N = 10, 20, 30. У 33 запросов оказалось меньше двух кандидатов для реранка.

| Модель | Реранк выполнен из 66 | Таймауты из 66 | p99 поиска для N = 10 / 20 / 30, мс |
| --- | ---: | ---: | ---: |
| Mixedbread | 0 | 66 | 405,098 / 405,186 / 408,139 |
| BGE | 13 | 53 | 405,093 / 405,107 / 405,098 |
| Qwen | 7 | 59 | 405,104 / 405,135 / 405,109 |

Это одиночные вызовы без HTTP. Прогоны реранкеров на `tune` и `test`, нагрузочный прогон M4 и серверный ONNX INT8 отложены. Критерии приёмки v1.1 пока не проверены полностью.

## Воспроизведение

```sh
python -m scripts.bench_rerank --model mixedbread --device mps --dtype float16 \
    --paraphrases tests/paraphrases.jsonl --split tune --top-n 10 20 30 --budget-ms 400
python -m scripts.bench_rerank_http --model mixedbread --device mps --dtype float16 \
    --data-dir "$VK_DATA_DIR" --top-n 10 --budget-ms 400
```

Для локального режима нужны зависимости `requirements-baseline.txt`, `requirements-embeddings.txt` и, для HTTP, `requirements-api.txt`. Для Qwen нужно `transformers>=4.51`, для конфигурации Mixedbread с `LogitScore` проверен `sentence-transformers==5.7.0`. Режим BGE ONNX INT8 дополнительно требует `onnxruntime` и `tokenizers` и принимает пути к локальным файлам модели и токенизатора.

Для интегратора: имя формата `rerank:<mixedbread|bge|qwen>:dated:bm25`, `top_n` и `budget_ms` — настройки при создании `RerankSearcher`. Создавать `TransformersScorer` один раз в `lifespan`, вызывать `RerankSearcher.close()` при остановке. До подтверждения метрик оставить `dated:bm25` вариантом по умолчанию.
