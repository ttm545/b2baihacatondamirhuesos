## Серверный замер по loopback

Сервер с одним vCPU, Intel Xeon Processor (Skylake, IBRS). Один процесс Uvicorn. Оба коммита запускались по очереди во временных контейнерах с одинаковыми зависимостями образа v1.0 и одним архивом из 16 376 писем, сверенным по SHA‑256. Порты доступны только через `127.0.0.1`.

Каждая строка — 1 000 успешных измеренных запросов по 99 публичным формулировкам, восемь клиентов, два прогревочных запроса на клиента. Во втором повторе порядок старта движков поменяли. Клиентское время включает обработку HTTP и ожидание на том же сервере. `took_ms` измеряется внутри маршрута и не включает ожидание до его входа.

Максимальный клиентский p99 у `period` — **271,7 мс**. При K=10 получили **160,7–183,9 мс**. Разброс 66–445 мс, ранее отмеченный на ноутбуке, при том же K в двух прогонах не повторился.

Под нагрузкой доля простоя CPU была 0.00%, а доля `steal` не превышала 0.12%. По CPU PSI хотя бы одна задача ждала CPU в 68,7–75,8% времени прогона `period`. Это подтверждает конкуренцию за единственное ядро при восьми клиентах. Сравнением `took_ms` и клиентских процентилей нельзя точно измерить вклад ожидания для отдельного запроса.

Публичный бэкенд v1.0 прошёл проверку до и после 12 000 измеренных вызовов. Временные контейнеры завершены. Публичное переключение выполняется после объявления `release/v1.1`.

Для повтора запустите оба коммита на локальных портах с `VK_SEARCHER=dated:bm25` и `VK_SEARCHER=period` соответственно и выполните скрипт из коммита `2266797` для каждого порта.

```sh
for k in 5 10 100; do
  python scripts/load_test.py --url "http://127.0.0.1:$BENCH_PORT" --queries "$VK_BENCHMARK_QUERIES" --clients 8 --calls 1000 --k "$k"
done
```
