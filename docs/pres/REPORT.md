Хакатон ФПМИ, кейс VK Tech «Умный поиск в Почте». Срез отчёта — 22 ноября 2026 года. Результаты выпуска относятся к поиску в выбранном почтовом ящике в версии **v1.1, 76576ae**. ## Итог проекта

Сделали веб-прототип умного поиска по **16 376 письмам в 12 синтетических ящиках**. Пользователь вводит обычную фразу, при необходимости добавляет период, видит распознанную тему и дату, открывает найденное письмо и может перейти к похожим уведомлениям. Прототип развёрнут по HTTPS. Бенчмарк работает с тем же движком и экспортирует ранжированные ID писем.

- **Без даты на всех 99 публичных запросах:** nDCG@5 **0,4512 у релиза против 0,1423 у обычного BM25**. Разница **+0,3089**, примерно в 3,17 раза по этой метрике. На этом парном срезе оценивается нахождение исходных размеченных писем.
- **С датой на 99 публичных запросах:** Recall@5 **0,8516**, nDCG@5 **0,9869**, nDCG@10 **0,9906**, MRR@5 **0,9949**, Recall@100 **1,0000**. Первое релевантное письмо в топ‑5 у **99 из 99** запросов.
- **32 отложенные перефразировки:** Recall@5 **0,5687**, nDCG@5 **0,6582**, nDCG@10 **0,7180**. Как минимум одно размеченное письмо попало в топ‑5 у **29 из 32** запросов.
- **На VPS:** **6 000 успешных вызовов** версии 1.1. При 8 клиентах и K=5, 10, 100 серверный p99 равен **216–342 мс**. Топ‑5 CLI и API совпал для **99/99** публичных запросов.

## Алгоритм релиза v1.1

**Общая часть.** Для выбранного ящика парсер выделяет тему и включительный период. Дата запроса определяет точку отсчёта для «вчера» и верхнюю границу доступности. Письма с известной более поздней датой исключаются. Письма с неизвестной датой остаются кандидатами общего поиска. Для BM25 используются леммы, поправка на длину документа, частота и больший вес темы.

**С датой.** Внутри периода отбираем до 30 кандидатов смесью **91,5% обычного BM25 / 8,5% семантического BM25 с Navec**. Баллы каждого канала нормируются относительно максимума. Navec учитывает до 24 близких лемм на слово с порогом косинуса 0,45. При слабом совпадении темы итоговый ансамбль смешивает текстовый порядок period, профиль period:cover и контекстный порядок с весами **35% / 20% / 45%**. При сильном совпадении сохраняется текстовый порядок. Тематические совпадения вне периода идут следом.

**Без даты.** Объединяем до 200 кандидатов из каждого из трёх источников: BM25, RuBERT с адаптером, контекстное пространство. Учитываем позиции в источниках и свежесть с периодом полураспада 30 дней. Веса релизного профиля приблизительно **22,13% BM25 / 29,13% RuBERT / 8,10% контекст / 40,64% свежесть**. Свежесть полезна на этом наборе, где целевые письма близки к дате запроса.

**Модели и эксплуатация.** RuBERT Tiny Retriever имеет **29 096 112 параметров без pooler**. Индекс писем содержит 312-мерные векторы, подготовленные заранее по теме и началу письма, до 80 токенов. Контекстная проекция имеет 64 координаты. Qwen3-VL-Embedding-2B, **2 127 532 032 параметра**, использовался офлайн для обучения проекции. Онлайн используется локальный RuBERT и готовый индекс. FastAPI и один Uvicorn работают в контейнере за Caddy.

Абляции меняют только текст запроса. Ящик, дата отсчёта и разметка сохраняются. Для недели, месяца и поиска без даты исходные qrels продолжают засчитывать письма одного дня. Проверка показывает, сохранилось ли целевое письмо, а полноценная оценка всех подходящих писем других дней потребовала бы новой разметки.

В публичном наборе все 99 формулировок задают день. Все 565 положительных пар приходятся на этот день. Потолок Recall@5 при предоставленной разметке — **0,8630**, поскольку у части запросов больше пяти релевантных писем. Организаторы сказали, что распределение запросов в приватном наборе такое же, как в публичном. Закрытое качество определяет их отдельный запуск.

## Ресурсы и p99

На VPS Intel Xeon Skylake, **1 vCPU**, **1,92 GiB RAM**, локальный HTTP по loopback, 8 клиентов, по 1 000 вызовов после прогрева на сценарий. Все 6 000 вызовов v1.1 успешны. Время внутри API измерено в took_ms, весь HTTP-вызов включает ожидание выдачи.

| Запросы | K | p99 внутри API, мс | p99 HTTP, мс |
| --- | ---: | ---: | ---: |
| С датой | 5 | 225,0 | 301,5 |
| С датой | 10 | 216,0 | 281,0 |
| С датой | 100 | 341,9 | 445,0 |
| Без даты | 5 | 216,3 | 235,2 |
| Без даты | 10 | 243,2 | 246,8 |
| Без даты | 100 | 241,9 | 309,4 |

На VPS RuBERT занимает **114 MiB**, Navec **51 MiB**, векторный индекс **9,8 MiB**, суммарно около **175 MiB**. Память контейнера в простое — **783,4 MiB**, лимит **900 MiB**. По журналу от запуска до готовности Uvicorn — **22,88 с**. Пиковая память и выделенная холодная индексация на VPS отдельно не измерялись. Исторический p99 493 мс относится к другой серии. Для защиты используйте явные условия серии из таблицы. [Исходные отчёты нагрузки](evidence/pitch/results/) · [Паспорт](evidence/pitch/results/passport.md)

## Факты для защиты

- **Что даёт смысловой поиск?** На одних и тех же 99 запросах без даты nDCG@5 вырос с 0,1423 у BM25 до 0,4512 у релиза. На исходных запросах с календарём основной вклад даёт интервал; семантика уточняет отбор и порядок.
- **Почему Recall@5 0,8516 при MRR@5 0,9949?** Первое нужное письмо обычно очень высоко. Если у запроса больше пяти нужных писем, топ‑5 физически не вмещает их все. Поэтому Recall и MRR отвечают на разные вопросы.
- **Что гарантирует p99?** Таблица показывает фактический замер на 1 vCPU при восьми клиентах и указанном K. Закрытые замеры организаторов выполняются на их данных и инфраструктуре.
- **Как показать демо?** В ящике `box-12259a301ee2` запрос «долг за съём муниципальной квартиры 19 августа 2028» выводит письма об оплате найма за эту дату. Для второго примера в `box-84bd433469cb` запрос «грузовик уже добрался до склада» без даты поднимает уведомление о прибытии автомашины в верх выдачи. Затем можно открыть письмо и перейти к похожему.
