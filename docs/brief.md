# Кейс: VK «Умный поиск в Почте»

Назначенный кейс команды. Источник — официальное условие [`docs/vk-mail-search.pdf`](vk-mail-search.pdf).
Дополнительные детали из раздела VK Tech презентации собраны в [краткой сводке](vk-search-summary.md). При расхождениях сверяйтесь с официальным условием.

## Суть

Пользователь помнит смысл письма, но не тему, отправителя или точные слова. Обычный полнотекстовый поиск такие письма не находит. Нужен поиск по смыслу, чтобы угадывать формулировки не приходилось.

## Что делаем

Веб-сервис — небольшой прототип почты:

- просмотр писем из предоставленного корпуса;
- умный поиск, который умеет больше простого полнотекстового.

Основной трек — поисковый движок. Способ реализации, алгоритмы, индексы и архитектуру выбираем сами. Обязательных пользовательских сценариев нет: свои возможности поиска выбираем и обосновываем сами.

Приоритет организаторов — быстрый поиск и собственная проработка алгоритмов, а не перенос всей задачи на большую языковую модель.

## Жёсткие требования

| Требование | Детали |
| --- | --- |
| Скорость | p99 времени поискового запроса строго **< 1 с**. Замер идёт от получения запроса сервером до готовой выдачи: обработка запроса, поиск и ранжирование. Сеть до браузера и отрисовка не учитываются. Нарушение даёт штраф, а не дисквалификацию. |
| Модели в поиске | На этапах retrieval и reranking модели через API или больше **3 млрд параметров** снижают оценку (без автодисквалификации). Вне поискового движка таких штрафов нет. |
| Ресурсы | Вычислительные ресурсы не ограничены. |

## Данные и оценка

- Архив анонимизированных писем. По презентации — около 16 000 писем в 12 синтетических ящиках.
- Публичный бенчмарк для разработки и самопроверки. По презентации — 99 запросов.
- Приватный бенчмарк остаётся у организаторов. Итоговые замеры качества и скорости проводят они сами, запуская наше решение.
- Метрики по презентации: Recall@K, nDCG@K, MRR@K.
- Формат выдачи для проверки по презентации: на каждый `query_id` — ранжированный список `doc_id`.

## Что сдаём

1. Репозиторий с исходным кодом и инструкцией запуска.
2. Работающую веб-демонстрацию: просмотр писем и поиск. Можно на localhost.
3. Проверяемый поиск — выдачу в формате бенчмарка.
4. Защиту проекта.

## Бонусы

- **+1 балл** — сервис развёрнут в интернете по публичной ссылке.
- **Дополнительный трек** (необязательно) — полезные функции почты помимо поиска. Нужно показать, какую задачу пользователя решает функция. Размер бонуса и критерии объявят отдельно.

## Пока не определено организаторами

- Формат бенчмарков, точные метрики и K, методика проверки.
- Размер штрафов за p99 и за модели, нагрузка при замере, набор запросов, правила прогрева и кэширования.
- Размер бонуса и критерии дополнительного трека.

Когда организаторы это объявят, дописываем сюда и отмечаем в чате.
