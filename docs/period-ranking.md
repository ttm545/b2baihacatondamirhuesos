# Переранжирование писем периода

У публичного набора VK все 99 запросов задают определённый день, и все 565 положительных пар относятся к этому дню. У v1.0 Recall@100 равен 1,000. Для части запросов релевантных писем больше, чем помещается в короткой выдаче, поэтому даже при идеальном порядке Recall@5 равен 0,8630, а Recall@10 — 0,9376.

`period` якорит период и отбирает кандидатов штатным `dated:bm25`. Он пересчитывает порядок первых 60 писем периода. Письма из других дней продолжают исходную выдачу. Оценка учитывает покрытие значимых слов с весами по их частоте в корпусе, отдельно тему и начало письма, близость слов и совпадения символьных триграмм. Результат объединяется с баллом и позицией BM25. При запросе без периода или без темы используется исходное ранжирование. Дополнительные данные для работы поисковика берутся из индекса, который строится при старте сервиса.

Коэффициенты обучены на 44 перефразировках `tune` и соответствующих исходных запросах. Для выбора регуляризации использована перекрёстная проверка с исключением целого семейства запросов. Профиль с коэффициентом регуляризации 0,003 получил nDCG@10 0,6345 в этой проверке против 0,5968 у v1.0. На этапе поиска используются только общие коэффициенты, текст запроса и содержимое индекса.

## Качество

Презентация VK приводит Recall@5 как пример Recall@K. [В условии](vk-mail-search.pdf) конкретный K оставлен для отдельного объявления. README архива организаторов тоже использует обозначение Recall@K. Для обоих движков проверены короткая выдача и полнота кандидатов.

| Набор | Поисковик | Recall@5 | nDCG@5 | Recall@10 | nDCG@10 | MRR@10 | Recall@100 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Публичный VK, 99 запросов | `dated:bm25` | 0,8479 | 0,9756 | 0,9263 | 0,9756 | 0,9832 | 1,0000 |
| Публичный VK, 99 запросов | `period` | **0,8516** | **0,9869** | 0,9322 | **0,9906** | 0,9949 | 1,0000 |
| Отложенные перефразировки, 32 запроса | `dated:bm25` | 0,5173 | 0,6285 | **0,7731** | 0,7029 | 0,7332 | 1,0000 |
| Отложенные перефразировки, 32 запроса | `period` | **0,5437** | **0,6518** | 0,7538 | **0,7103** | 0,7443 | 1,0000 |

Публичная таблица включает часть исходных запросов, использованных при обучении. Отложенная часть использует четыре других семейства запросов. На ней по nDCG@10 и MRR видно небольшое улучшение, но Recall@10 снизился на 1,93 процентного пункта. Recall@20 вырос с 0,8762 до 0,8862. Увеличение глубины переранжирования с 60 до 100 сохранило приведённые метрики@10 на обоих наборах. Результат закрытого бенчмарка будет получен при запуске организаторами.

Профиль `period:cover` с ручными весами получил Recall@5 0,8496 на публичном VK и 0,5750 на отложенных перефразировках. Выбранный обученный профиль получил лучший публичный Recall@5 и nDCG@10 среди проверенных полевых профилей. Профиль `cover` доступен для повторной проверки на другом наборе запросов.

## Задержка

Windows, Intel Core i5-13420H, один процесс Uvicorn, восемь одновременных клиентов. Для каждой ячейки выполнено 1 000 HTTP-запросов плюс прогрев. Все запросы успешны. Серверный p99 взят из `took_ms`, loopback p99 включает путь до готового JSON и очередь. Измерения относятся к этому компьютеру и публичной нагрузке.

| Вариант | K | p99 на сервере | p99 через loopback |
| --- | ---: | ---: | ---: |
| `dated:bm25` | 5 | 146 мс | 229 мс |
| `period` | 5 | **175 мс** | **349 мс** |
| `dated:bm25` | 10 | 193 мс | 305 мс |
| `period` | 10 | **142 мс** | **277 мс** |
| `dated:bm25` | 100 | 216 мс | 364 мс |
| `period` | 100 | **295 мс** | **452 мс** |

В первом прогоне `period` loopback p99 составил 445 мс при K=10 и 520 мс при K=100. При отдельном экспорте на 99 запросах p99 вызова поиска составил 50,5 мс при K=5 и 60,7 мс при K=100. Индекс строился за 15–20 с до начала поисковых вызовов. Экспорт глубиной пять совпал с первыми пятью результатами экспорта глубиной сто для каждого запроса.

## Что сравнивали

На 44 запросах `tune` переранжирование по одной насыщенной частоте полей получило nDCG@10 0,5813, по покрытию полей 0,6176, с добавлением BM25 0,6284. Линейный профиль получил 0,6347 после обучения на всём `tune`.

- Многоязычный MiniLM в INT8 дал 0,6492 на `tune` при обработке до 16 пар, но p99 локального пути составил 6,34 с на одном потоке. Группировка похожих писем и ограничение до восьми пар дали 0,6332 и 1,06 с. Ограничение до четырёх пар дало 0,6124 и p99 0,71 с. [Экспорт MiniLM](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1/tree/1427fd6/onnx)
- Статические многоязычные эмбеддинги Potion в смеси с покрытием получили 0,6287. В конфигурации по умолчанию веса нейросетей и внешние API отсутствуют. [Модель Potion](https://huggingface.co/minishlab/potion-multilingual-128M/tree/73908c3)

## Воспроизведение

Сначала задайте `VK_DATA_DIR` по инструкции в README. Экспорт можно запустить на любом входном JSONL в формате бенчмарка.

```sh
python -m vk_mail_search.predict --queries data/queries_dev.jsonl --out predictions.jsonl --k 100
python -m vk_mail_search.evaluate --pred predictions.jsonl --k 5
python -m vk_mail_search.evaluate --searcher period --k 100
python -m vk_mail_search.evaluate --searcher period --paraphrases tests/paraphrases.jsonl --split test --k 100
python -m vk_mail_search.evaluate --searcher dated:bm25 --paraphrases tests/paraphrases.jsonl --split test --k 100
python -m uvicorn vk_mail_search.api:app --host 127.0.0.1 --port 8000
python scripts/load_test.py --url http://127.0.0.1:8000 --queries data/queries_dev.jsonl --calls 1000 --clients 8 --k 5
```

Для переобучения установите NumPy и SciPy и выполните `python -m scripts.fit_period --data-dir data`. Сравнение дополнительных профилей выполняется через `python -m scripts.compare_period --data-dir data --split tune`. Для прогона MiniLM требуются `onnxruntime`, `numpy`, `tokenizers` и файлы `model_quint8_avx2.onnx`, `tokenizer.json` в каталоге `--minilm-dir`. Для Potion требуются `safetensors`, `numpy`, `tokenizers` и файлы `model.safetensors`, `tokenizer.json` в каталоге `--potion-dir`.
